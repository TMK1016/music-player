# 本機播放與原生 EQ：實作與驗收

2026-10-24｜v0.2｜沿用已獲使用者確認的科技藍視覺。

## 本輪交付

從純介面進入本機音訊垂直切片：批次選檔、音樂庫副本、內容去重、原子索引保存、播放／暫停／定位、播放進度、順序／隨機／整份循環與實際 10 段 EQ。這些功能對目前 Mac 開發版本生效；iPhone／實車驗證另計。

本機沒有 Rust 編譯器，未擅自安裝至工作區外。現階段以 `AudioPlayback` 協定隔離 Apple 原生後端，用作之後 Rust DSP 的參考與對照；Rust 核心仍未完成。這不代表原規劃中的 Rust、限幅器、參數平滑或完整音訊 QA 已完成。

## 檔案與儲存

- `LibraryStore.swift`：actor 序列化匯入；使用 security-scoped URL；驗證系統可解碼、1～2 聲道、長度有效且可讀取開頭 PCM。
- 匯入時串流計算 SHA-256，以固定大小區塊避免把整個檔案載入記憶體；同內容不同檔名略過。
- 先複製至暫存、再次核對複本雜湊，再移至內容定址檔名；JSON 索引原子提交，失敗回復本次紀錄與新副本。原始使用者檔案不移動、不刪除。
- 檔案存於 App Application Support 的 `OrcaPlayer/Library/`。未啟用 sandbox 的 Mac 開發建置通常位於 `~/Library/Application Support/OrcaPlayer/Library/`；未來 sandbox 版本由系統導向 App 容器。
- 索引損毀時拒絕覆寫，顯示需先備份再修復。未提供自動刪除或猜測重建。
- 已包含 WAV 原創測試片段 `ORCA Soundcheck`，18 秒／44.1 kHz／雙聲道。以本機腳本合成，可重建，不使用網路音樂或第三方錄音。
- 曲目標題目前使用來源檔名，不宣稱已解析 ID3／專輯封面。自訂命名歌單、來源刪除／重新連結與大量曲庫效能仍待後續。

## 真實音訊管線

```text
App 內完整音檔 → AVAudioFile 系統解碼 → AVAudioPlayerNode
  → AVAudioUnitEQ（10 段、每段 1 octave）
  → 前級補償 → mainMixer 音量 → 系統輸出裝置
```

實際前級由 EQ 的 `globalGain` 套用，示意順序表示功能關係，不代表新增獨立處理節點。10 個中心頻率為 32／64／125／250／500／1k／2k／4k／8k／16k Hz，增益 ±12 dB、0.5 dB 步進。高於音檔取樣率可用範圍的頻段會旁通。介面仍是固定中心頻率 EQ，未開放頻率與 Q 編輯。

前級補償保守採「正增益總和＋3 dB」衰減，最高 96 dB；旁通濾波時保留相同補償，避免切換時突然恢復到較大音量。這是靜態餘裕措施，**不是限幅器或絕對不削波的保證**。尚未建立完整效果切換平滑與等響度比較機制。

Apple 擁有即時回呼；沒有在音訊回呼中做使用者檔案複製、雜湊、JSON 或 UI 更新。切歌／定位使用排程代次取消舊 completion，避免 stop 導致的舊回呼誤跳歌。自然播畢使用 `.dataPlayedBack` 回呼，再由主執行緒更新歌單狀態。進度讀取 player 的實際 sample time，每 0.2 秒更新 UI，並非以假計時器代替音訊時間。

輸出配置改變時先暫停並提示重新播放；iOS 加入系統中斷與拔線暫停處理，但尚未經真機驗證。沒有宣稱已完成背景播放、鎖屏遙控、CarPlay 或無縫路由恢復。

## 驗收結果

| 項目 | 結果與證據 |
| --- | --- |
| Mac 原生建置 | arm64 Debug 編譯通過；本機 App 可開啟 |
| iOS 建置 | generic Simulator arm64 編譯通過；CoreSimulator 服務仍不可用，未執行手機測試 |
| 匯入／去重 | 同內容不同檔名：新增 1 首、略過 1 首；壞音檔獨立回報，不阻斷已成功項目 |
| 保留來源與離線副本 | 原始檔保留；測試移除測試用來源後，App 副本仍可解碼出 18×44100 frames |
| 重啟還原 | 新建 LibraryStore 可讀回相同曲目；EQ／音量／匯入曲目收藏序列化還原通過 |
| 損毀索引 | 匯入被拒絕，原損毀內容未被覆寫 |
| 播放狀態 | 以注入後端檢查選歌、暫停、恢復、定位、EQ 傳遞、尾曲停止、循環與中斷 UI 狀態 |
| 真實播放入口 | Mac App 按播放後狀態轉為播放、進度由實際音訊 sample time 前進；以原創低振幅片段驗證，未據此宣稱主觀音質提升 |
| 原生 PCM／EQ | 獨立原生驗證 App 以 AVAudioEngine 離線渲染，1 kHz 頻段設定 +6 dB 相對旁通實測 **+6.00 dB**；旁通補償相對原音基線 **−6.00 dB** |
| 低取樣率 | 16 kHz 處理格式下 8k／16k 頻段旁通，避免不成立的中心頻率 |

命令列環境能執行檔案／狀態檢查，但無法註冊 AVAudioPlayerNode 音訊單元；直接做離線音訊測試曾因系統元件不可用中止。後改用獨立原生驗證 App 完成同一 PCM 測試，未降低安全設定。螢幕擷取服務曾報錯，仍以驗證 App 寫出的結果檔確認上述數值；不將擷取錯誤誤列為驗證成功。

## 重現

在專案根目錄執行 `python3 scripts/check_audio.py`。它會執行隔離的檔案與狀態檢查，並產生 `apps/apple/.build/checks/NativeEQValidation.app`；以 Finder 開啟該 App 進行不出喇叭的原生離線測試，結果寫至同目錄 `native-eq-result.txt`。測試不需要使用者音樂、帳號或網路。

原始證據：`.build/checks/results.log`、`.build/checks/native-eq-result.txt`、`.build/macos-build.log`、`.build-ios/ios-build.log`。建置與測試暫存未納入版本控制；本文件保留當次結論與方法。

## 尚未驗收

WAV 已建立明確驗收；其他系統可讀音檔會逐檔驗證，不代表所有 MP3／AAC／ALAC／FLAC 變體均已通過。本輪未做完整格式矩陣、60 分鐘連播、CPU／耗電、拔線實測、多通道／車機／iPhone 真機測試。iCloud 自動下載、第三方下載、自訂歌單、Rust DSP 與對外簽章公證未完成。
