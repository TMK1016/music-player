# V11 視窗統一與封面定位修復

版本：0.18.0／build25。依使用者六張 20261029151922／151930／152002／152006／152012／152017 標註圖實作。

## 修復內容與原因

封面錯位並非歌曲分類錯誤：V10的詳情名稱／曲目讀取選定ID，但輪播第一次顯示沒有明確在版面建立後定位到該ID，因此從第二個項目進入時仍顯示第一張暗化照片。V11以局部scroll位置接收版面報告，完成初始版面後明確scrollTo選定ID，再開放輪播位置回寫；外部改名／重新選定時也同步定位。使用者手動滑動時，已相同的ID不再重複捲動，避免互相追趕。

- 新增／編輯清單及歌手共用 EntityDetailsForm：左上標題、置中照片與右上相機選單、白色名稱欄及無藍底取消／儲存按鈕。新歌手可在建立時選圖並使用既有裁切。
- 歌曲編輯的底部按鈕也取消背景；照片選單仍沿用原先框選裁切流程。
- 補齊照片選單的「移除照片」：編輯器明確傳入replace旗標，nil才代表儲存成預設圖片；既有程式未指定旗標時維持舊的保留封面語意，避免其他入口意外刪圖。
- 歌手數量位於左側，與全部歌曲的數量同為caption與muted色；減少主捲動區頂部padding及零高錨點間距，右側排序保留44pt觸控尺寸。
- 首頁清單下拉50pt以上且以垂直方向為主時展開全部，不再顯示「顯示全部／收合」文字按鈕。點首頁回到預覽狀態；輔助使用仍有展開／收合動作。
- 首頁左滑切到下一分類、右滑切到上一分類；至少60pt且水平大於垂直1.3倍才切換，在首尾停止、不循環。短距離、斜向或正在拖曳排序時不切換，保持原本垂直捲動／排序入口。
