# V6 播放穩定、封面與曲庫管理

2026-10-27｜0.13.1／build17｜英文完整需求：docs/en/v6-reliability-artwork-import-v013.md。

## 需求與行為

- 右側功能抽屜持續保留原生輸出元件，收合只控制顯示／互動，不在按下時建立原生元件；六項順序保留。照片、排序及資料編輯不呼叫選曲或重接音訊。
- 全部歌曲支援長按拖曳與往上／下移替代入口；順序保存在collection-v1.json的可選songOrder欄，舊版仍能解碼，新匯入歌曲接在後面，刪檔移除順序引用。
- 歌曲可設定個別封面；顯示優先序為個別封面→對應歌手頭貼→既有原創圖。清除個別封面可恢復歌手備援；照片不修改外部音檔。
- 歌曲、歌手、清單共用裁剪流程：中央方框／圓形參考、三分線、拖曳、縮放與置中；使用照片後才改草稿，取消不改。ImageIO先修正方向與縮至1024像素，輸出JPEG；來源上限20 MB，保存檔仍受5 MB限制。
- 歌手大圓頭貼＋名稱及次要資訊，展開歌手／清單顯示白亮邊。迷你播放器改成內縮圓角藍底及青色邊框。
- 單曲右側「⋯」開操作面板，集中收藏、黃星評分、編輯歌曲、加入清單、移除當前自建清單及刪除App副本；刪檔仍二次確認、外部來源保留。
- 設定依附圖改成一致列樣式，移除歌曲綁定／更多設定群組入口。保留原有綁定資料與播放頁單曲策略，日誌在首頁側邊欄。
- 「搜尋本機歌曲」先選資料夾，雷達只在掃描時旋轉；完成後列出可讀音檔、排除已入庫及本次重複內容，手動勾選才匯入。支持全選／取消，不自動下載雲端佔位檔。重新掃描後只保留尚未入庫候選；上限10,000個音檔，達上限會明確提示分資料夾處理。

## 雜音處理與證據界線

使用者已回報：按功能抽屜、修改歌手頭貼及截圖時短暫雜音。未有真機音訊錄波／系統xrun資料，因此不能把推測寫成已確認的唯一根因。

已發現可避免的工作：每次View更新以UIImage/NSImage同步解碼原圖；分類改動在MainActor同步JSON編碼與原子磁碟寫入；抽屜條件顯示反覆建立AVRoutePickerView；同步音效時即使參數相同仍重寫濾波器。本輪用背景ImageIO actor＋有界24 MB解碼快取、FIFO背景分類寫入、常駐輸出元件與原生後端相同參數略過處理。預設原創Canvas亦改為非同步繪製並套用Equatable隔離。

iOS首次啟動播放前請求46 ms I/O緩衝，避免為離線播放器追求過低延遲；只請求一次，不在抽屜、照片或截圖時改音訊Session。實際值由系統決定，記錄在OSLog的audio-continuity分類；這不是46 ms必定生效、也不是完全無雜音保證。EQ響應／前級策略未變更。

## 驗收情境

| 情境 | 預期結果 | 證據狀態 |
| --- | --- | --- |
| 播放中連續開關右側抽屜、截圖10次 | 音樂不中斷、無新噪音，輸出路由不改 | 真機聽測待完成 |
| 播放中更換歌手／歌單／歌曲照片、裁剪後儲存 | 不重載音檔；封面正確、取消保留前圖 | 模型及原生UI分開驗證 |
| 無歌曲封面→有歌手圖→個別封面→清除 | 依優先序顯示且重啟保存 | 自動檢查 |
| 全部歌曲重排後重啟、再匯入／刪除 | 順序保存、沒有遺失或重複曲目 | 自動檢查 |
| 橫／直照片裁剪，拖至邊緣 | 不出界、不變形，框內內容與保存一致 | 幾何檢查＋原生UI |
| 空資料夾、相同內容、壞音檔、未下載檔 | 空結果／排重／略過理由，不自動匯入 | 自動及裝置檢查分開 |
| 搜尋中取消或關閉 | 停止結果更新，釋放授權範圍 | 程式及裝置檢查分開 |

## 真機掃描記憶體修復

首次V6 0.13.0／16測試安裝後，在真機掃描實際資料時，Xcode暫停於Task306的LibraryStore.hash→readCandidate→scanFolder，EXC_RESOURCE高水位限制3072 MB，觀察2.87 GB記憶體、491.9 MB/s磁碟。這是本輪新取得的實際失敗證據，不能沿用先前Running宣稱交付完成。

處理：雜湊每1 MiB讀取以autoreleasepool包覆，掃描每個檔案／列舉步驟及背景JSON寫入也各自釋放Foundation暫存；圖片快取成本同時計入來源Data與解碼像素。這針對長actor工作可能累積橋接讀取緩衝的具體風險；最終版提高到0.13.1／17避免與失敗測試版混淆。新增512 MiB檔連續兩次雜湊的壓力回歸及記憶體量測；仍須真機原資料夾重掃驗證。
