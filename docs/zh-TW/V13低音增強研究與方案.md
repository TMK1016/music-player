# V13：低音增強研究與預計方案

查證：2026-10-29。狀態：**研究完成／演算法尚未改動／方案未實作**。手機仍為0.19.3／build29。本輪使用PM test-scenarios方法定義驗收，Firecrawl連線失敗（ENOTFOUND api.firecrawl.dev），以可用網頁工具查證第一手資料。此為與播放器相關的核心專業資料整理，不能宣稱窮盡所有調音知識或所有市售產品。

## 1. 結論與目標

有公開可用的濾波與響度／峰值計算方法，但沒有一個通用公式能在所有歌曲、所有喇叭上同時達成「低音更強、整體一樣大、人聲原封不動、峰值不變、動態不變」。對已接近峰值上限的音源，加強低頻需要額外餘裕；餘裕不足就要降低增強、降低全頻增益，或接受限制／壓縮。

本專案先推薦 **A：透明低架＋依歌曲實測、受真峰值約束的音量管理**。不先加入會改變音色的諧波生成，不先以持續壓縮換響度。A的目標是移除不必要的保守衰減，而非保證任何歌都維持原音量；若在滿電平歌曲上仍不達期望，再評估B。

「不降低聆聽效果」分開驗收：感知響度、人聲／高頻相對平衡、低音量感與輪廓、瞬態／動態、數位失真、手機效能與喇叭實際失真。數位RMS、LUFS、dBTP與車內dB SPL不是同一量。

## 3. 目前App究竟做什麼

核對 `AudioPlayback.swift:SoundEffectSettings.apply`、`EQHeadroom.swift`、`EQBands.swift`：

- 七段固定EQ：50／125／315／800／2000／5000／12500Hz，頻寬4/3倍頻程。
- 低音：Apple AVAudioUnitEQ的lowShelf，轉折／中點參數90Hz，0～+9dB（十個整數位置；舊小數設定保留）。不是把90Hz以下硬切一刀，過渡區平滑延伸。
- 合成響應估算涵蓋EQ及低架重疊。前級為 `−min(96, 3 + max(0, 合成最高增益) + 有效殘響預留)` dB；殘響非零時另留6dB。
- 沒有LUFS測量、true-peak限制器、內容相關低音動態控制或諧波增強。頻率響應估算不是任意波形瞬態／真峰值上限。

**可推導的例子，非新PCM聽測：**七段全平、無殘響時，低音0的前級約−3dB；低音+6的最高響應約+6，因此前級約−9dB。深低頻合計約−3dB，高頻合計約−9dB。相較低音0，深低頻絕對電平接近原本，但中高頻少了約6dB，因此更像「把其他聲音壓小」。此為目前策略的取捨，不是喇叭一定有故障。

+6dB約為訊號振幅2倍；在相同阻抗、仍線性的理想假設下，電功率約4倍，不能據此推算實車增益或安全音量。App全頻衰減也不必然等同聲音細節消失，但會改變同一旋鈕位置的聽感。

## 4. 頻率、音色與硬體限制

常用溝通分區約20～60Hz偏深沉／延伸，60～120Hz偏低鼓量感，120～250Hz涉及厚度與混濁；分界不是統一標準，也不是Fiesta校正數據。既有50／125Hz與90Hz低架會重疊，必須看整條合成曲線。人聲基音與低中頻也可能重疊，不能保證加低音人聲完全不受影響。

目前經藍牙送往車機的是整體立體聲，App不知道每個單體振幅、線圈溫度、功放餘裕及車機自己的EQ／loudness／限幅。[TI Smart Amp](https://www.ti.com/lit/an/slaa625d/slaa625d.pdf)使用喇叭建模與熱／振幅等資料做控制，這與手機通用低音效果不同。故手機無法只憑車名復刻硬體保護；不恢復已刪除的車輛設定。

## 5. 可套用的公式與邊界

### 5.1 低架濾波（公開標準方法）

來源：[W3C Audio EQ Cookbook](https://www.w3.org/TR/audio-eq-cookbook/)。定義G為低頻端增益dB、f0為低架中點、fs為取樣率、S為坡度：

```text
A = 10^(G/40)
w0 = 2*pi*f0/fs
alpha = sin(w0)/2 * sqrt((A+1/A)*(1/S-1)+2)
c = cos(w0); beta = 2*sqrt(A)*alpha
b0 = A*((A+1)-(A-1)*c+beta)
b1 = 2*A*((A-1)-(A+1)*c)
b2 = A*((A+1)-(A-1)*c-beta)
a0 = (A+1)+(A-1)*c+beta
a1 = -2*((A-1)+(A+1)*c)
a2 = (A+1)+(A-1)*c-beta
```

各係數除以a0後，以標準biquad差分式處理；S=1為該定義下單調棚架的陡峭選擇，不能當成所有UI的Q=1。Apple內部係數未公開，W3C模型須與Apple實際PCM比較，不能假定完全相同。線性IIR在高於轉折區可保持接近0dB幅度，但仍有相位變化，並非所有頻率都原封不動。

### 5.2 音量補償＋真峰值約束（建議方法，不是ITU指定補償器）

[ITU-R BS.1770-5](https://www.itu.int/rec/R-REC-BS.1770-5-202311-I)規範響度／真峰值量測，不規範我們一定要用哪種低音效果或補償目標。

```text
Lref = 參考路徑的量測響度（LUFS）
Lwet = 增強路徑未做最終增益前的量測響度（LUFS）
Pwet = 同一路徑左右聲道最大的真峰值（dBTP）
C = 工程選定的輸出真峰值上限，例如先測 -1 dBTP
Delta_match = Lref - Lwet
Delta_peak = C - Pwet
g = min(Delta_match, Delta_peak)  # 此處不含額外增益範圍限制
out[n] = 10^(g/20) * wet[n]
```

這是一個**已完整分析該歌曲／該參數組合**後的靜態增益選擇，不是用LUFS去捉瞬態。若Delta_peak較小，只能比目標安靜；不得再用另一個Auto Gain補回造成削波。須在輸出重新量測，處理gating改變、量測誤差、殘響尾音與取樣率差異。−1dBTP為初始候選，並非所有平台規定，也不保證後續藍牙編碼／功放／喇叭零失真。

Bass研究先以「同一組七段EQ／同一殘響，低音關閉」為參考，隔離低音影響；日後比較不同EQ模式，才另選統一原聲參考。讓單一GainManager管理既有前級／最終補償，防止兩份headroom與makeup疊加。不要直接刪除3dB預留而沒有替代驗證。

RMS能用 `10*log10(Eref/Ewet)`近似能量補償，但不是感知響度；靜音與極低能量不能直接相除。LUFS也不能完整預測每個人對低頻的感覺。

### 5.3 動態低音（方案B的概念式）

```text
Gtarget(t) = clamp(Guser - k*max(0, Lbass(t)-T), 0, Guser)
a = exp(-1/(tau*fs))
Gsmooth[n] = a*Gsmooth[n-1] + (1-a)*Gtarget[n]
```

當低頻能量高於T，減少額外增強，使用不同attack／release平滑。k、T、tau是要經量測及聽測調整的參數，不是通用最佳值；慢速RMS偵測不能取代峰值安全路徑。不要任意逐樣本直接跳換biquad係數；新係數須確認穩定，採可驗證平滑或雙路交叉淡化。左右共用增益控制，避免音像左右晃動。

### 5.4 諧波生成（方案C的概念式）

```text
bass = band_limit(input)
harmonics = remove_DC_and_filter(nonlinearity(bass) - linear_component)
out = dry + mix*harmonics
```

例如非線性可產生較高諧波；所需階次、包絡、交互調變及混合量要調校，這不是MaxxBass的公開完整配方。需超取樣與抗混疊設計、避免直流、完整輸出峰值管理。這是刻意改變音色，不稱「無失真還原」。

## 6. 預計方案比較

| 方案 | 方法 | 預期效果 | 代價與適用 |
|---|---|---|---|
| **A 優先：透明低架＋內容量測增益** | 先保留90Hz與原0～9dB語意，0／3／6／9為測試點；分析候選輸出LUFS／TP，選受峰值限制的靜態補償；平滑切換 | 有實際餘裕的歌曲不再一律付出最壞情況的衰減；不引入持續動態壓縮／新諧波 | 完整分析有成本；峰值緊的歌仍可能變小。先分析目前歌曲及選定參數，快取而非千首×所有模式預掃 |
| B 低頻動態控制＋必要的真峰值限制 | 低頻很強時少加；僅偶發尖峰啟用左右連動lookahead limiter | 更能維持日常響度、避免低鼓長期推著全頻下降 | 改變動態，有抽動／鼓頭變鈍、延遲及CPU風險；若limiter常工作應降低增強，不硬追音量 |
| C 感知諧波增強 | 從低頻產生可重播的較高諧波，限量混回 | 小喇叭可能更容易辨認低音旋律，未必增加極低頻負擔 | 改變音色，可能粗糙或干擾人聲；可選音色模式，非原音預設 |

次低頻／subharmonic生成先不推薦作通用模式，因會新增更低的能量並增加硬體負擔。低音單聲道化、立體擴展、殘響、車內量測校正是另一類問題，不與本輪綁在一起。

A先保留原有十段UI、模式及設定相容，避免同時改增益管理、轉折頻率及刻度而無法歸因。+9dB只作上限／壓力情境，不當成所有喇叭建議值；日常試聽先比較+3／+6，不保證這是每首歌最佳值。80／90／100Hz及不同坡度待A驗證後一次只比較一項。

## 7. 開發順序與驗收情境（尚未執行的新測試）

1. **基線儀表**：錄下現有實際Apple路徑的輸入／輸出LUFS、sample peak、true peak、RMS、合成響應、延遲、render耗時與欠載；比較低音0／3／6／9、全平及50／125Hz正增益重疊。輸出數據後才量化改善幅度。
2. **A離線原型**：同一首歌、同一參數組合完整渲染與量測，計算g；加入靜音、短片段、seek、切歌、殘響尾音與44.1／48／96kHz。靜音不補增益，未完成分析走現有保守路徑，不宣稱已等響。長曲分析不得阻塞播放或UI。
3. **A正式串流實作**：量測及快取在背景，render內不讀檔、不配置大量記憶體、不鎖等待、不重建圖；參數改變取消過時分析，以歌曲內容雜湊、EQ／bass／FX參數、取樣率及演算法版本作快取鍵。完整串接分析而非只看低架。切換採候選20～50ms交叉淡化並驗證峰值／相位影響，不聲稱固定時間必然無聲。
4. **真機等響A/B**：語音、人聲流行、原音低音提琴、電子深低音、強鼓、大動態古典、已重度壓縮及本身失真的母帶。比較舊版／A／bass-off，固定車機其他EQ設定，停車操作並等響比較，不以「較大聲」當品質勝出。手機自帶喇叭／耳機／藍牙車機分開記錄。
5. **決策門檻**：峰值允許時，整曲響度匹配目標差≤0.5LU；受峰值限制時明確記錄差額，不將該歌標成等響通過。候選輸出≤−1dBTP、容許量測差0.1dB須以獨立測量器核對；無NaN／Inf、額外數位削波、切換爆音。這不是保證修好來源原有失真。滑桿平滑後無可重現click，效能以真機callback期限與欠載檢查，不先虛構CPU百分比。
6. **只有A不足才評估B**：依實際曲庫統計哪些歌仍受峰值限制。另設limiter增益衰減的深度／時間占比、低頻動態及聽測門檻，再決定是否接受動態代價。C保留為獨立可選模式。

無完整曲庫量測，不能填「音質提升幾％」或預告全部歌曲都不變小。無渲染／聽測的新結果，僅有本輪原始碼稽核、資料查證與未來驗收方案；不重跑UI建置或部署沒有變更的音訊程式。
