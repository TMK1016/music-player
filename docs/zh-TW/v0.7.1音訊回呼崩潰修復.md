# v0.7.1 音訊回呼崩潰修復

2026-10-26。使用者回報手機仍像舊版，Xcode出錯。先前只驗證部署產物及短暫Running，未證明播放與持續運行正常；後續修正此交付判斷。

## 實際證據

Xcode顯示已連接iPhone程序暫停，engine序列執行緒出現EXC_BREAKPOINT。LLDB thread backtrace all確認鏈為：_dispatch_assert_queue_fail → _swift_task_checkIsolatedSwift → NativeAudioPlayer.init的closure #1 → Combine Subscribers.Sink → AVAudioEngineImpl::IOUnitConfigurationChanged。這不是一般編譯錯誤，也不能把其他SessionCore警告當成同一根因。

## 修復

AudioNotificationBridge在nonisolated函式建立明確@Sendable訂閱，通知可以來自引擎執行緒，再將action送回MainActor。原本只在繼承主actor的sink內建立Task仍太晚：runtime會先在進入sink時檢查actor，尚未進Task就中止。iOS中斷／路由通知與播放完成closure也標為@Sendable，資料及UI仍只在MainActor處理，不關閉Swift並行檢查。

設定頁加入Info.plist讀取的版本與build，v0.7.1／10。此號碼是手機可直接核對入口，避免只看相似畫面或App名稱。保留既有bundle識別碼及資料，不刪App或曲庫。

## 回歸測試

新增實際NotificationCenter背景執行緒發送測試，使用正式AudioNotificationBridge，確認處理函式於MainActor執行；不需音訊硬體。CLI模型測試通過，並保留現有分類／播放／計次／清理／EQ回歸。後續需真機重新部署並核對持續運行；新UI與完整背景／藍牙驗收仍不是單一測試能保證。
