## 配置理由

採用 50、125、315、800、2000、5000、12500 Hz，與 Pioneer 官方車用 7 段配置相同。相鄰中心比值約 2.5（約 1.32～1.35 倍頻程）；採約等距的對數分佈，而非把線性 Hz 範圍等分。這是合理的車用音色控制配置，不宣稱為唯一標準或 Fiesta 專用校正。

| 中心頻率 | 概念分區（相鄰中心的幾何中點） | 主要用途 |
|---|---|---|
| 50 Hz | 約 20～79 Hz | 低頻重量與延伸 |
| 125 Hz | 約 79～198 Hz | 低頻厚度與衝擊 |
| 315 Hz | 約 198～502 Hz | 溫暖與混濁感 |
| 800 Hz | 約 502～1265 Hz | 中頻與聲音主體 |
| 2 kHz | 約 1.27～3.16 kHz | 人聲存在感 |
| 5 kHz | 約 3.16～7.91 kHz | 清晰度與銳利感 |
| 12.5 kHz | 約 7.91～20 kHz | 亮度與空氣感 |

以上分區只是閱讀概念，不是互斥的濾波範圍。各段使用約 1⅓ 倍頻程的參數濾波，彼此平順重疊；20 Hz 與 20 kHz 不代表控制效果相同或硬體可重播全部頻率。90 Hz 低音增強仍獨立保留，與 7 段 EQ 一起估算餘裕。

來源（2026-10-24 查證）：[Pioneer 官方規格](https://pioneer-car.eu/asset/user_manuals/UPLOAD_ID_12913/7c041202cb86fe43de682d7ece4e4922d0285916)。只參考中心頻率；本 App 的 0.5 dB 步進、頻寬、餘裕與 UI 是本專案的工程選擇。

## 介面與操作

順序為：EQ 開關 → 目前增益分佈示意 → 7 個垂直滑桿 → 模式列。滑桿以容器寬度等分，不放在橫向 ScrollView 中。曲線仍是控制值示意，不是實車頻響。

模式列只佔一行、可橫向捲動；橫向互動會展開完整模式選擇面板，也提供「全部」按鈕作明確替代入口。iOS 18／macOS 15 以上使用 scroll-phase 互動事件，較舊部署版本使用方向判斷的拖曳手勢。完整面板以自適應格狀排列，並提供模式管理選單。

右上「自訂」保存目前 7 段 EQ、低音與空間設定。新增後立即加入同一份模式清單並捲動至新增項目；最多 20 組，可重新命名、覆蓋或刪除。自訂刪除與內建移除都會解除相關歌曲綁定；內建移除可還原，自訂刪除需先確認。這些選項在列中長按或完整面板的更多按鈕操作。

## 舊資料相容

- 設定格式升為 v3，仍讀取 v1／v2。
- 舊 10 段控制值先限制合法範圍，再在對數頻率軸插值為 7 段。不是單純丟掉三個數值。
- 13 組內建模式另以 7 段重新安排；自訂模式保留 ID、名稱、低音、空間與歌曲綁定。收藏、音量、音樂庫與車輛設定不重置。
- 段數與頻寬不同，轉換不能保證舊音色完全相同。首次遷移前，原始偏好 Data 另存同 App 的 UserDefaults key `orca.ui.settings.before7band`，只建立一次，避免覆寫原始備份。現行設定仍使用原 key，舊音樂庫路徑不變。
- 可移除的內建模式另存 hiddenPresets；不相容／無效的模式綁定會被過濾。

## 驗證

- 模型測試通過：每個內建模式為 7 段、對數插值、舊自訂 ID／命名／歌曲綁定保留、v3 寫入、內建移除／持久化／還原、移除時解除綁定。既有自訂 20 組上限與播放／匯入測試通過。
- Apple 原生離線 PCM：130 個探測點，16／44.1／48 kHz；最大模型誤差 0.033 dB、最大低估 0.016 dB。800 Hz 單段 +6 dB 實測 +6.00 dB，旁通保留補償差 −6.00 dB；90 Hz 低架在 32 Hz 實測約 +5.90 dB。
- 360 點寬原生預覽截圖確認七段同時顯示，滑桿區沒有橫向捲動；實際操作 50 Hz +3 dB、建立「七段試聽」、清單出現、完整面板、面板內新增入口與刪除測試模式皆通過。預覽使用獨立 bundle ID，不改寫正式 App 偏好。
- 橫向捲動自動展開已接入，桌面自動操作的 scroll 工具回報 noWindowsAvailable，故不能宣稱此手勢已由該工具實測；「全部」入口已實測。手機手勢與實車聽感仍需實際確認。

最終 macOS arm64 Debug 與 generic iOS Simulator arm64 Debug 建置通過。Xcode 真機產物為 v0.6.0／7，日誌與來源一致，並顯示實體 iPhone 的 Running 狀態。流程校驗：25 節點、11 日誌版本、32 項改動，HTML／原生日誌一致，技術範例與來源一致，JavaScript 語法通過。這次維持合成響應餘裕策略，未加入響度補償、限制器或座位距離功能。
