# Music Player 產品需求基準

2026-10-25｜PM 導入版。依 project-pm、create-prd 整理；為既有產品的管理基準，不重寫歷史驗收。產品負責人：使用者；Orca 負責協作與證據整理。

新版功能/UIUX已於2026-10-26具體補充，詳見[UIUX規格](UIUX-首頁與播放體驗.md)。下文先前的候選描述保留規劃脈絡，涉及頁面、清單、評分及人工資料整理時，以該規格的明確需求為準；待決策仍未凍結，未宣稱已實作。

## 1. 摘要

協助擁有自有音檔、希望在手機與車內離線聽歌的人，集中管理歌曲並保存個人調音。第一階段先讓本機匯入、播放與七段 EQ 穩定可用，再增加曲庫整理與個人化體驗。

## 2. 背景

使用者目前先在電腦取得音檔再轉入手機，想簡化入庫與聽歌流程。已完成 SwiftUI／Apple 音訊參考實作及部分真機啟動驗證，尚未完成完整格式、長時間播放、背景／路由與實車驗收。Rust 核心仍是規劃，不是現行實作。

## 3. 目標與成功標準

已確認目標：離線播放、自訂調音、降低音檔整理負擔。以下為工程驗收目標，不是既有使用數據或商業承諾：

1. 支援矩陣內的測試檔匯入後，移除外部原檔與斷網仍可播放；重啟後曲庫及模式保留。
2. 以指定測試佇列連播 60 分鐘，沒有崩潰、意外停播；中斷及路由變更符合明確恢復規則。
3. 七段完整顯示、模式原位展開、20 組上限、每曲綁定及舊資料遷移情境通過。

真實使用成功指標另記錄：匯入至播放所需操作、任務完成率、主觀滿意度；尚無基準，不捏造改善百分比。音質改善需控制條件試聽／量測，不以音量大小代替。

## 4. 使用族群

首要：以手機播放自有音檔、在車內透過藍牙聽歌，想保存聆聽偏好的人。首位驗證者為使用者本人，車輛 Fiesta 2017、無外接 DSP。

次要候選：需要依歌手、清單、評分整理本機曲庫的人；來自筆記構想，尚無訪談或市場驗證。首版不擴大至專業多通道調音族群。

## 5. 價值主張（六部分）

| 部分 | 首要族群 | 次要候選族群 |
|---|---|---|
| 誰 | 手機離線與車內聽歌者 | 本機曲庫整理者 |
| 為何 | 想穩定播放並快速套用個人調音 | 想更快找到熟悉或較少聽的歌 |
| 原來做法 | 電腦取得檔案後手動搬至手機 | 用檔名、資料夾或現有播放器分類 |
| 如何 | 驗證後複製入庫、離線播放、保存 EQ 與歌曲綁定 | 待確認的歌手標籤、清單、評分與篩選 |
| 之後結果 | 原檔不在仍能聽，調音可重用 | 分類與選曲結果可預期、資料可保存 |
| 替代方案 | 系統或其他本機播放器；差異假設是調音整合，尚未做競品驗證 | 既有曲庫軟體；差異尚待驗證 |

價值陳述：讓自有音檔的離線播放與個人調音在同一個 App 完成；先證明可靠性，再擴充整理與選曲功能。

## 6. 解法與範圍

核心旅程：選取檔案 → 驗證／去重／複製 → 曲庫選歌 → 播放 → EQ → 儲存模式 → 可選歌曲綁定。開發管理旅程：筆記或節點註解 → 明確交辦 → 更新需求與驗收 → 實作 → 證據 → 流程日誌。

已有：本機副本、播放控制、七段 EQ、低音與立體聲殘響、自訂模式與車輛資料。先驗證可靠性及手勢；不把「已寫程式」視為整體驗收完成。

後續候選：首頁／正在播放／設定導覽、最近 10 首、歌手與標籤、播放清單、五顆星與兩種隨機、聆聽統計。筆記中的「正在播放：在中下」尚不完整，須先提供介面稿討論。三顆星同時屬於兩種模式是原筆記明確包含的邊界，不能自行改成互斥。

技術：現為 SwiftUI＋AVAudioEngine，透過 AudioPlayback 隔離。保留既有資料識別碼。前後喇叭配置不等於可逐單體控制；藍牙仍按左右立體聲能力處理。

## 7. 假設、限制與未決策

- 實體 iPhone 已用於開發測試；正式首發平台、最低 OS、背景／鎖屏與發佈範圍仍需凍結。
- iCloud Drive 系統選檔不等於已驗證離線下載；須驗收雲端占位檔及中斷。
- YouTube 下載保留原需求，但未具備來源授權證據，不列入可開發承諾；不重複研究已有政策文件，接近實作時再查官方現況。
- 播放清單、歌手標籤、評分與統計只有筆記意圖，尚未授權本輪直接實作。
- 不重新加入座位距離／延遲；不宣稱 Dolby、逐喇叭 DSP 或最佳音質。

## 8. 交付順序

Now：可靠的本機離線與調音驗收。Next：先曲庫資料模型，再清單／評分，再首頁導覽與統計。Later：iCloud 完整匯入、發佈準備及有前提的來源／車用擴充。使用相依與出口條件安排，不在未知容量下編造日期或工期。
